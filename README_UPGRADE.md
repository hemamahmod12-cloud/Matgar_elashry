- ✅ فحص أمني تلقائي بـ CodeQL.
- ✅ إصلاح تلقائي للتنسيق عند كل Pull Request.
- ✅ مراقبة صحة الموقع كل 30 دقيقة مع فتح Issue عند الفشل.

- ✅ سكريبت ترحيل آمن للأدوار من JSON القديم إلى مجموعة `roles`.
- ✅ نسخة احتياطية من `firestore.rules` قبل أي تغيير.
- ✅ مسودة قواعد حديثة في `firestore.rules.upgrade-draft` للمراجعة؛ لم تُفعّل تلقائيًا لأن بنية التطبيق الحالية تعتمد على `storeData` القديمة.

## ما يجب تنفيذه يدويًا بعد المراجعة

1. توفير مفتاح Firebase خارج Git باستخدام `SERVICE_ACCOUNT_KEY` أو المسار الافتراضي `serviceAccountKey.json`.
2. تشغيل `npm run migrate:roles` بعد أخذ نسخة احتياطية والتحقق من مشروع Firebase الصحيح.
3. اختبار `firestore.rules.upgrade-draft` في Firebase Emulator، ثم ترحيل التطبيق والبيانات قبل نشره كقواعد فعالة.
4. تفعيل Branch Protection على `main` من Settings → Branches.

> لا يتم تنفيذ ترحيل الأدوار أو نشر قواعد Firestore تلقائيًا داخل CI، لأن ذلك قد يغيّر صلاحيات الإنتاج أو البيانات دون مراجعة.
